# L1 — the evidence-artifact layer

**L1** is the next profile above [L0](#/contract). It is **purely additive**: every
L0 rule still holds, on the same `evidence: "0.1"` contract version (see decision
[0027](#/decisions)). Where L0 records *that* a run happened in a parseable shape,
L1 requires the **captured proof** to travel with the pack: per-test execution
logs, a place for per-step screenshots, and a global coverage directory. A
**finalized** pack is **L1-valid** if and only if it is **L0-valid** *and*
satisfies the L1 artifact rules below; before finalize, L1 is structure-only (see
[Validating L1](#validating-l1)).

L1 adds **no new fields** to `run.yaml` or `result.yaml`. It is a layer of
sibling **artifacts**, and — like the L0 [definition](#/contract) — those
artifacts are **opaque**: evidence-cli checks their existence, naming, and
*declared* format, but never parses their bytes. The only artifacts it parses are
two small declarations, `logs/meta.yaml` and `video.yaml`.

## The L1 tree

```
<name>.evidence/
  run.yaml                          # L0
  coverage/                         # L1 — GLOBAL, required: the directory must exist
  tests/<id>/
    <definition>, result.yaml       # L0
    logs/                           # L1 — required
      meta.yaml                     #   declares the logs (see below)
      <declared files…>             #   opaque — ndjson | har | log
    steps/                          # L1 — required
      <ordinal>-<id>/               #   one folder per captured step (e.g. 1-open-checkout/)
        screenshot.<ext>            #   opaque — any image format
    video.<ext>                     # L1 — OPTIONAL inline video (opaque)
    video.yaml                      # L1 — OPTIONAL pointer: { url, …meta }
    issues/                         # L1 — reserved, not yet validated
```

"Required" below means **required once `status: finalized`**; on a `running` /
`aborted` pack these directories need not exist yet (see
[Validating L1](#validating-l1)).

| Artifact | Scope | L1 | Validated |
| --- | --- | --- | --- |
| `logs/` + `logs/meta.yaml` | per test | **required** (finalized) | meta parsed; declared files exist & contained |
| `steps/<ordinal>-<id>/screenshot.<ext>` | per test | `steps/` **required** (finalized) | each folder present maps to a step & has a screenshot |
| `coverage/` | global | **required** (finalized) | directory exists (contents open) |
| `video.<ext>` / `video.yaml` | per test | optional | `video.yaml` parsed when present |
| `issues/` | per test | reserved | — |

## Logs — `tests/<id>/logs/meta.yaml`

Each test declares the logs it kept. The framework chooses *which* logs **and how
to label the format** — both are open vocabulary, because evidence-cli never reads
the bytes.

```yaml
# tests/checkout/logs/meta.yaml
logs:
  - { name: console, file: console.ndjson, format: ndjson }
  - { name: network, file: network.har,    format: har }
```

- `logs:` MUST list **at least one** entry.
- Each entry MUST carry `name`, `file`, and `format`. Both `name` and `format` are
  **open, non-empty strings** — evidence-cli validates presence only, never the
  vocabulary (the same stance as step [`kind`](#/contract) and metric `type`,
  decisions [0009](#/decisions)/[0012](#/decisions)). Common formats are `ndjson`,
  `har`, `log`, but `csv`/`jsonl`/`txt`/anything is equally valid.
- Each `file` MUST be a **contained** relative path inside `logs/` (no `..`, no
  leading `/`, no scheme — same rule as `definition.path`) and the file **MUST
  exist**. Its contents are never parsed.

## Steps — `tests/<id>/steps/`

Per-step screenshots live in folders named for the step they belong to:

```
steps/
  1-open-checkout/ screenshot.png
  3-see-confirmation/ screenshot.webp
```

- Each subfolder is named `<ordinal>-<id>` and MUST match a `result.yaml` step —
  both the `ordinal` and the `id` must agree.
- Each subfolder MUST contain a `screenshot.<ext>` (any image format — opaque).
- **Not every step needs a folder** — L1 requires the `steps/` directory (at
  finalize), not a screenshot per step. A folder that maps to **no** step is an
  error; a step with no folder is fine.

## Coverage — `coverage/`

A single **global** `coverage/` directory at the pack root MUST exist. Its
internal structure is intentionally **open** for now; only its presence is
checked.

## Video (optional)

A test MAY include a video, in either form:

- **inline** — a `video.<ext>` file (any video format), opaque; or
- **pointer** — a `video.yaml` carrying at least a `url` (plus any extra meta).

`video.yaml` is parsed and checked when present; an inline video is never parsed.

## Validating L1

`evidence validate <target> --profile L1` runs **every L0 check, then the L1
additions** — profiles are an additive **chain** (`L1 → [L0, L1]`). L1 is
**status-gated exactly like L0** (decision [0018](#/decisions)): the *presence* of
the artifact directories is required only once the pack is sealed, because
`coverage/` is an end-of-run artifact and `logs/`/`steps/` fill in as a run
progresses — demanding them mid-run would fail a perfectly healthy in-flight pack.

| Run status | L1 checks |
| --- | --- |
| `running` / `aborted` | **Structure-only** — validate the *shape* of whatever artifacts already exist: `logs/meta.yaml` parses & conforms, declared log files are contained and present, each `steps/<ordinal>-<id>/` is well-formed, matches a step, and has a screenshot, `video.yaml` parses. Absence of `logs/`/`steps/`/`coverage/` is **not** an error. |
| `finalized` | **Full L1** — the above, **plus** `logs/` (with `meta.yaml` + ≥1 declared log), `steps/`, and the global `coverage/` MUST be present. |

The report also carries the pack's **current `status`**, so a host always knows
the lifecycle state alongside the findings.

`finalize` is **unchanged** by L1 — it already seals every artifact in the
directory into the flat `.evidence` zip; it derives L0 totals/hashes and seals,
and never validates.

See decision [0040 — L1 profile](#/decisions).
