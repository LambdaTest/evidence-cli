# L1 — the evidence-artifact layer

**L1** is the next profile above [L0](#/contract). It is **purely additive**: every
L0 rule still holds, on the same `evidence: "0.1"` contract version (see decision
[0027](#/decisions)). Where L0 records *that* a run happened in a parseable shape,
L1 requires the **captured proof** to travel with the pack: per-test execution
logs, a place for per-step screenshots, and a global coverage directory. A
**finalized** pack is **L1-valid** if and only if it is **L0-valid** *and*
satisfies the L1 artifact rules below; before finalize, L1 is structure-only (see
[Validating L1](#validating-l1)).

L1 adds **no new fields** to `run.yaml` or `result.yaml`. It is a layer of
sibling **artifacts**, and — like the L0 [definition](#/contract) — those
artifacts are **opaque**: evidence-cli checks their existence, naming, and
*declared* format, but never parses their bytes. The artifacts it parses are the
small declarations: `logs/meta.yaml`, `video.yaml`, and the two levels of
`failure.yaml` (see [Failures](#failures)).

## The L1 tree

```
<name>.evidence/
  run.yaml                          # L0
  failure.yaml                      # L1 — run-level failure INDEX, generated by finalize
  coverage/                         # L1 — GLOBAL, required: the directory must exist
  tests/<id>/
    <definition>, result.yaml       # L0
    logs/                           # L1 — required
      meta.yaml                     #   declares the logs (see below)
      <declared files…>             #   opaque — ndjson | har | log
    steps/                          # L1 — required
      <ordinal>-<id>/               #   one folder per captured step (e.g. 1-open-checkout/)
        screenshot.<ext>            #   opaque — any image format
        failure.yaml                #   step-level failure record (see Failures)
    video.<ext>                     # L1 — OPTIONAL inline video (opaque)
    video.yaml                      # L1 — OPTIONAL pointer: { url, …meta }
```

"Required" below means **required once `status: finalized`**; on a `running` /
`aborted` pack these directories need not exist yet (see
[Validating L1](#validating-l1)).

| Artifact | Scope | L1 | Validated |
| --- | --- | --- | --- |
| `logs/` + `logs/meta.yaml` | per test | **required** (finalized) | meta parsed; declared files exist & contained |
| `steps/<ordinal>-<id>/` | per test | `steps/` **required** (finalized) | each folder present maps to a step; missing `screenshot.<ext>` is a **warning** |
| `coverage/` | global | **required** (finalized) | directory exists (contents open) |
| `video.<ext>` / `video.yaml` | per test | optional | `video.yaml` parsed when present |
| `steps/<ordinal>-<id>/failure.yaml` | per step | optional (advisory when a failed/broken step lacks one) | parsed; anchored to its step; references contained & existing |
| `failure.yaml` (pack root) | global | **required** (finalized) — generated by `finalize` | parsed; rows agree with their pointers; complete against the records present |

## Logs — `tests/<id>/logs/meta.yaml`

Each test declares the logs it kept. The framework chooses *which* logs **and how
to label the format** — both are open vocabulary, because evidence-cli never reads
the bytes.

```yaml
# tests/checkout/logs/meta.yaml
logs:
  - { name: console, file: console.ndjson, format: ndjson }
  - { name: network, file: network.har,    format: har }
```

- `logs:` MUST list **at least one** entry.
- Each entry MUST carry `name`, `file`, and `format`. Both `name` and `format` are
  **open, non-empty strings** — evidence-cli validates presence only, never the
  vocabulary (the same stance as step [`kind`](#/contract) and metric `type`,
  decisions [0009](#/decisions)/[0012](#/decisions)). Common formats are `ndjson`,
  `har`, `log`, but `csv`/`jsonl`/`txt`/anything is equally valid.
- Each `file` MUST be a **contained** relative path inside `logs/` (no `..`, no
  leading `/`, no scheme — same rule as `definition.path`) and the file **MUST
  exist**. Its contents are never parsed.

## Steps — `tests/<id>/steps/`

Per-step screenshots live in folders named for the step they belong to:

```
steps/
  1-open-checkout/ screenshot.png
  3-see-confirmation/ screenshot.webp
```

- Each subfolder is named `<ordinal>-<id>` and MUST match a `result.yaml` step —
  both the `ordinal` and the `id` must agree. A malformed name or a folder that
  maps to **no** step is an **error**.
- A subfolder SHOULD contain a `screenshot.<ext>` (any image format — opaque);
  its absence is a **warning**, not an error — not every framework captures a
  frame per step (an API or unit run has none). The warning keeps the signal for
  dashboards without failing the pack.
- **Not every step needs a folder** — L1 requires the `steps/` directory (at
  finalize), not a screenshot per step. A step with no folder is fine.

## Coverage — `coverage/`

A single **global** `coverage/` directory at the pack root MUST exist. Its
internal structure is intentionally **open** for now; only its presence is
checked.

## Video (optional)

A test MAY include a video, in either form:

- **inline** — a `video.<ext>` file (any video format), opaque; or
- **pointer** — a `video.yaml` carrying at least a `url` (plus any extra meta).

`video.yaml` is parsed and checked when present; an inline video is never parsed.

## Failures

A **failure record** is the structured explanation of why one step did not pass —
expected vs. actual, the error, page/console/network state at failure, and an
optional post-hoc **triage** block. It lives at two levels (decision
[0044](#/decisions)); both files are parsed, everything they *point at* stays
opaque (containment + existence checked, never read).

### Step level — `steps/<ordinal>-<id>/failure.yaml`

Authored by the framework (or a triage agent), sibling of the step's screenshot.

```yaml
step: pay                                # REQUIRED — = folder id + a result.yaml step
status: broken                           # REQUIRED — verdict enum; cross-checked
expected: receipt screen shown           # ┐ evidence-of-what: error.message,
actual: payment API timed out            # ┘ or expected + actual (REQUIRED)
page_state:
  url: https://store.example/checkout    # external URL — open, never checked
  screenshot: steps/2-pay/screenshot.png # file reference ✓ contained + exists
console_at_failure:
  ref: logs/console.ndjson               # file reference ✓
error: { message: ERR_TIMED_OUT calling api.stripe.com, type: NetworkTimeout }
triage:                                  # OPTIONAL — strictly shaped when present
  status: triaged                        #   enum: untriaged|triaged|in_progress|dismissed
  by: { kind: agent, id: claude, at: 2026-07-06T09:05:00Z }   # at: date-time
  rca: { root_cause: CI egress firewall blocked 443, confidence: 0.8 }
  verification: { status: not_verified } #   enum: not_verified|verified|refuted
```

- **Required core:** `step` (must equal the containing folder's `<id>` **and**
  match a `result.yaml` step — an error otherwise), `status` (verdict enum), and
  **evidence-of-what**: `error.message`, or both `expected` and `actual`.
- **File references** — `repro.definition`/`repro.resolved`,
  `page_state.{dom,a11y,screenshot}`, `console_at_failure.ref`,
  `network_at_failure.ref`, `triage.rca.evidence[]`,
  `triage.suggested_fix.patch` — resolve **relative to the test root**
  `tests/<id>/` (one unambiguous base, regardless of the record sitting one
  level deeper). No `..`, no leading `/`, no scheme; the target must exist.
  URLs are open strings, never checked.
- **Triage is strict when present**, open vocabulary elsewhere
  (`locator_context`, `error.type`, `rca.category`, `linked_defects`, …).
- A record whose `status` disagrees with its step's `result.yaml` status is an
  advisory **warning**; so is a failed/broken step with no record (at
  finalized). Neither fails the pack.

### Run level — `failure.yaml` at the pack root

**Generated by `finalize`**, never hand-authored: one denormalized row per step
record, sorted by test then ordinal, written before the atomic seal. A clean run
still gets the file (`failures: []`), so its presence is unconditional once
finalized.

```yaml
generated: 2026-07-06T09:01:00Z          # finalize's endedAt
totals: { failures: 1, triaged: 1, untriaged: 0 }
failures:
  - test: checkout
    ordinal: 2
    step: pay
    status: broken
    path: tests/checkout/steps/2-pay/failure.yaml   # pack-root-relative pointer
    triage_status: triaged               # lifted from the record when present
```

The index must be **truthful** — each row's `path` must equal
`tests/<test>/steps/<ordinal>-<step>/failure.yaml`, every pointer must resolve,
and every record present in the pack must be indexed. All three are **errors**:
the index is machine-generated, so a gap means tampering or a stale index.
`finalize` fails fast on a step record that does not parse or lacks a string
`status` — it mirrors, it never validates.

## Validating L1

`evidence validate <target> --profile L1` runs **every L0 check, then the L1
additions** — profiles are an additive **chain** (`L1 → [L0, L1]`). L1 is
**status-gated exactly like L0** (decision [0018](#/decisions)): the *presence* of
the artifact directories is required only once the pack is sealed, because
`coverage/` is an end-of-run artifact and `logs/`/`steps/` fill in as a run
progresses — demanding them mid-run would fail a perfectly healthy in-flight pack.

| Run status | L1 checks |
| --- | --- |
| `running` / `aborted` | **Structure-only** — validate the *shape* of whatever artifacts already exist: `logs/meta.yaml` parses & conforms, declared log files are contained and present, each `steps/<ordinal>-<id>/` is well-formed, matches a step, and has a screenshot, `video.yaml` parses, any `failure.yaml` (step record or root index) parses, is anchored, and its references/pointers resolve. Absence of `logs/`/`steps/`/`coverage/`/failure records is **not** an error. |
| `finalized` | **Full L1** — the above, **plus** `logs/` (with `meta.yaml` + ≥1 declared log), `steps/`, the global `coverage/`, and the root `failure.yaml` index MUST be present; a failed/broken step without a failure record earns an advisory warning. |

The report also carries the pack's **current `status`**, so a host always knows
the lifecycle state alongside the findings.

`finalize` seals every artifact in the directory into the flat `.evidence` zip;
it derives L0 totals/hashes, **generates the run-level failure index** (its one
generative artifact — decision [0044](#/decisions)), and seals. It never
validates.

See decisions [0040 — L1 profile](#/decisions) and
[0044 — failure records](#/decisions).
